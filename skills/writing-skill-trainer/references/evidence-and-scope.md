## 1. 观察与规则

不要从“这篇文章很有感染力”直接跳到“Skill 要求有感染力”。中间至少经过三步：

1. 找到可观察动作：作者先放什么信息、如何转折、何时解释、怎样结束；
2. 找到读者效果：这个动作解决理解、信任、情绪、决策还是行动问题；
3. 写成可执行规则：下一次写作时，何时做什么；缺少条件时不做什么。

| 类别 | 判断 | 放置位置 |
|---|---|---|
| `invariant` | 多篇重复、跨题型仍成立 | 核心 `SKILL.md` |
| `conditional` | 只在某题型、渠道或目标中成立 | `references` 的题型模块 |
| `incidental` | 单篇才出现，或只是表层习惯 | 校准报告，不进入 Skill |
| `safety` | 授权、隐私、事实、版权或法律边界 | 核心边界或独立安全模块 |

“表层特征”包括小标题数量、编号格式、段落长度、反问数量、数字数量、CTA 句式、加粗方式和固定开头。除非用户明确要求品牌硬规范，否则它们默认是旋钮，不是配额。

## 2. 证据台账

每一条候选规则使用一行，并保存为独立台账；短引只用于定位，不建立可复制的句子库：

| 字段 | 示例 | 说明 |
|---|---|---|
| `rule_id` | `R-VOICE-02` | 稳定编号，后续评分和日志引用它 |
| `observation` | 先呈现具体异议，再给结论 | 写动作，不写性格形容词 |
| `source_refs` | `post-03.pdf:p2,p5` | 文件、页码、段落或标题 |
| `evidence_note` | 两处先问后答，一处直接结论 | 用转述，避免长引 |
| `effect` | 降低读者防备并建立问题意识 | 说明读者功能 |
| `scope` | `core` / `conditional` / `incidental` / `safety` | 规则范围 |
| `confidence` | `high` / `medium` / `low` | 基于重复度和证据完整度 |
| `negative_case` | 家庭故事篇从回忆进入 | 记录例外，防止绝对化 |
| `promote_to` | `SKILL.md` 或 `references` | 本轮是否晋级 |

一个合格的规则应能回答：

- 在什么任务或题型中使用？
- 具体执行动作是什么？
- 有什么材料或证据支持？
- 什么时候不使用？
- 如果没有素材，如何安全降级？

## 3. 规则晋级

采用“证据强度 × 作用范围”的晋级策略：

| 证据 | 允许的结论 |
|---|---|
| 单篇、单次出现 | 只能写入该篇报告，标记 `incidental` |
| 同一题型至少两篇 | 可写入题型模块，附适用条件 |
| 至少三篇、至少两种题型 | 可候选为核心规则，必须通过回归 |
| 用户明确指定的品牌硬要求 | 可直接进入核心，但标记为 `user_constraint`，不要伪装成作者统计规律 |
| 来自源文但真实性/授权不明 | 不晋级为事实；只保留为待核验风险 |

晋级前做反例检查：主动寻找没有该特征的文章。如果反例属于同一题型且效果没有下降，规则应改成可选旋钮；如果反例属于不同题型，应拆成条件规则。

## 4. 防过拟合回归

### 4.1 留出策略

- 1 篇：只做同文校准，不能宣称泛化；
- 2—4 篇：至少留出 1 篇不参与规则提炼；
- 5 篇以上：按题型分层留出，或使用逐篇 leave-one-out；
- 每次修改后，必须重跑原测试集和留出集。

验证集不得反向提供人物、数字、标题、金句或章节结构。它只用于判断规则是否有效。

### 4.2 模板坍缩检查

并排比较源文与候选稿，记录：

- 开头是事件、问题、回忆、结论还是其他形式；
- 是否都被迫使用相同数量的小节和相同小标题；
- 没有数字的文章是否被硬加算例；
- 家庭故事是否被改成观点清单；
- 服务文章是否被改成广告；
- 每篇是否被强行添加相同 CTA、免责声明或作者身份卡。

如果三篇以上共享同一表层形状，先撤销表层硬规则，再重新检查底层功能，而不是继续添加例外。

## 5. 版权、身份与事实

- 迁移结构、论证动作、节奏机制和适用边界，不迁移独特连续表达；
- 直接引语必须有原始记录和使用授权；PDF 引号只能证明页面呈现，不自动证明真实对话；
- 源文中的事实、人物、产品和数字不是新文章的事实授权；缺条件时转述、泛化、假设或暂停；
- 不冒充来源作者，不把来源的姓名、履历、联系方式和品牌锚点写进新 Skill；
- 对包含客户、疾病、家庭冲突或未成年人信息的文章，先做脱敏和公开范围判断；
- 评分不能奖励抄写。原创安全是独立门槛，不以“更像”为理由放宽它。

## 6. 进化报告

报告至少包含：

1. 输入样本数量、题型和授权状态；
2. `invariant`、`conditional`、`incidental`、`safety` 规则数量；
3. 测试提示和留出策略；
4. baseline/candidate 每轮盲评结果、最低维度与预测命中情况；
5. 每次修改的证据、假设、预期收益和实际结果；
6. keep/revert 决定及原因；
7. 模板坍缩、事实、版权和授权风险；
8. 最终状态：`validated`、`provisional` 或 `blocked`。

没有实测子 agent 时，明确写 `eval_mode: dry_run`，不要把模拟分数写成真实效果提升。单篇台账可以帮助形成假设，但不能把规则状态写成 `validated`。

## 7. 输出相似性复核

版权复核不依赖一个机械的“相似度百分比”。候选稿完成后：

1. 对照源文检查连续重复的独特短语、固定比喻、署名和结尾；
2. 如有字符串扫描工具，标记未经用户要求而重复的长连续片段，交给人工判断；
3. 对必要的术语、公共表达和用户明确授权的短引，不把机械命中直接判为抄袭；
4. 把复核结果写入报告，任何未解决的身份或版权疑问都阻断晋级。
