## 1. 自动失败项

任一项出现，当前候选版本不得晋级：

- 编造源文没有支持的人物、事实、引语、数字或经历；
- 复制来源的独特连续表达、固定署名，或让读者误以为来源作者亲自发布；
- 把单篇事实、产品结论、人物细节或视觉配额写成所有文章都必须遵守的规则；
- 忽略用户指定的任务、读者、渠道或输出格式；
- 为追求风格分数删除会改变结论的条件，或把不确定内容写成确定事实；
- 授权、隐私、版权或关键事实存在明确阻断，却把结果标记为可发布/已验证。

自动失败项优先于总分。增加免责声明不能修复核心事实、结构或版权错误。

## 2. 默认评分卡

先按每项 0—10 评分，再乘以权重：

| 维度 | 权重 | 主要问题 |
|---|---:|---|
| 任务与读者适配 | 15 | 是否完成用户目的，是否对目标读者有效 |
| 结构与因果推进 | 15 | 事件、问题、证据、转折和结论是否相互推动 |
| 语言、声音与节奏 | 15 | 人称、句长、口语度、密度和声音是否可辨 |
| 说理机制与证据功能 | 15 | 类比、数字、对话、细节是否承担清楚的论证功能 |
| 场景、情绪与作者在场 | 10 | 有证据的生活后果、观察和服务动作是否被保留 |
| 价值交付与行动收束 | 10 | 是否让读者获得判断，结尾是否与任务自然相连 |
| 泛化与表层自由度 | 10 | 能否适配其他题型，是否避免固定模板坍缩 |
| 原创、事实与安全 | 10 | 是否可追溯、不过度复制、不冒充且边界清楚 |

总分：

`总分 = Σ（维度得分 ÷ 10 × 权重）`

默认门槛：无自动失败项、总分 ≥85；跨文章验证时，“泛化与表层自由度”不得低于 7/10；单篇只能标记 `provisional`，不能因为高分宣称泛化。门槛只用于最终通过判定；每轮 keep/revert 用 §3.5 的成对比较裁决，不比较绝对分数。

## 3. 评分解释

### 3.1 0—3：失败

任务偏离、结构断裂、声音完全泛化、证据失真，或有明显安全问题。

### 3.2 4—6：可读但不稳定

部分机制出现，但依赖模板、解释悬空、场景被削弱，或只在源文上有效。

### 3.3 7—8：合格

主要机制被保留，候选稿完成任务，局部仍需精修；规则有条件且可解释。

### 3.4 9—10：稳定

候选稿既保留底层功能又保留表层自由度；跨题型仍有效，且没有以复制或虚构换取相似感。

评分时同时写三句话：

1. 最高分维度的具体证据；
2. 最低分维度和造成失分的一个原因；
3. 下一轮只应改变哪一条规则。

### 3.5 评分卡诊断，成对比较裁决

单次 LLM 绝对打分噪声通常在 ±1 分以上，1—2 分的总分差异大概率是噪声。因此：

- 评分卡只用于**诊断**：定位最低分维度，决定下一轮改什么；
- keep/revert 用**盲评成对比较**裁决：评审接收源文、用户任务和两份匿名稿件（不知道哪份是新版本），回答哪份更好完成任务、是否保留机制与声音、是否引入模板化/虚构/版权风险；
- 候选稿不必在每一项都高于 baseline；若在源文上胜出、在留出集下降，判定为过拟合，拒绝该修改。

## 4. 测试提示模板

保存为 `evals/test-prompts.json`。`expected` 只写可观察行为，不写答案：

```json
[
  {
    "id": "happy-path-01",
    "source": "sample-a.md",
    "prompt": "根据给定文章提炼的写作 Skill，重写这篇同主题文章；保留事实，不复制独特句子。",
    "expected": "完成用户任务，保留核心结构机制，输出原创且可追溯的稿件。",
    "type": "same-task",
    "holdout": false
  },
  {
    "id": "transfer-01",
    "source": "sample-b.md",
    "prompt": "将同一写作机制用于不同题型，允许改变开头、结构和结尾形式。",
    "expected": "迁移底层机制，不强行复制源文表层模板。",
    "type": "transfer",
    "holdout": true
  }
]
```

至少包含一个 `same-task` 典型提示和一个 `transfer` 迁移/复杂提示。单篇样本的 `transfer` 只能标记为压力测试，不得作为独立文章泛化证据。用户未确认测试范围时，先停在测试设计阶段。

## 5. 进化日志

`reports/results.tsv` 可使用以下表头：

```tsv
timestamp	run_id	version	prompt_id	pairwise_result	lowest_dimension	prediction_hit	status	eval_mode	note
```

`status` 使用 `baseline`、`keep`、`revert`、`blocked`；`eval_mode` 使用 `full_test` 或 `dry_run`；`pairwise_result` 使用 `win`、`lose`、`tie`；`prediction_hit` 使用 `yes`、`no`（预期改善的维度是否真的改善）。只有盲评胜出且留出集没有明显退化才写 `keep`。

每轮改动记录格式：

```text
假设：把规则 R-STRUCT-02 改为条件规则，能减少家庭故事的模板化。
证据：sample-a 第3段、sample-c 结尾；sample-b 没有该特征。
变更：只调整题型路由，不新增固定小标题。
预期：泛化维度改善，源文声音不下降。
结果：盲评 candidate 胜出（2/3 提示）；holdout 未退化；预测命中；决定 keep。
```

连续两轮 `prediction_hit: no` 时触发预测校准停机（见 SKILL.md §9.1）：停止爬山，回到证据提炼阶段重新诊断。

## 7. 裁判审计日志

rubric 在单个 run 内冻结；本节格式用于 run 之间的外环审计（见 SKILL.md §9.3）。

发现"评分结论与用户实际判断相悖"的案例时，追加一行到 `reports/rubric-audit.md`：

```text
案例：candidate v3 总分 88 通过，用户判断"模板感重、不像作者"。
指向缺陷：泛化与表层自由度维度未捕捉到小标题句式趋同。
状态：待累积（1/2）。
```

同一缺陷累积 2 个以上案例后，才允许在下一个 run 开始前修改一次 rubric；修改记录追加：

```text
变更：泛化维度评分问题中加入"连续小节句式是否趋同"检查项。
依据：案例 #1、#3。
版本：rubric v2（v1 保留于 git 历史或备份）。
```

进化循环进行中不得修改 rubric。
