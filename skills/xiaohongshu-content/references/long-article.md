# 小红书长文：HTML 图文编排到发布

## 适用场景

长文适合严肃叙事、公司故事、事件复盘和需要证据链的深度分析。目标不是把文章截图成一张超长图，而是在小红书原生「写长文」编辑器中得到可阅读、可重排的图文内容。

## 交付物

归档到 `posts/<日期>-<slug>/`：

- `note.md`：标题、来源、标签、发布说明、全文和状态。
- `article/article.html`：完整视觉稿与本地预览的单一真源。
- `article/assets/`：Image 2 插图、官方页面或报道的实时截图；截图文件名说明来源。
- `article/article-preview.png`：发布前视觉核对用，不要把整张预览图当作文章上传。

严肃长文默认不用 emoji。事实、日期、金额和出处先双源核验；生成插图只能表达概念，证据必须使用实时截图并在图注中标明来源与截取日期。

## 写作与 HTML

建议正文 1500–3000 字，结构为：导语 → 4–6 个二级标题 → 关键引用/数据 → 结论与接话问题 → 资料与口径说明。标题仍按账号打法尽量控制在 20 字以内。

HTML 视觉稿可以有完整 CSS，但粘贴进小红书编辑器时只传语义片段：`p`、`h2`、`blockquote`、`ol/ul`、`strong`、`br`。平台不会保留任意 CSS，也不要指望本地图片路径或 data URL 随 HTML 一起上传。

## 编辑器入稿

1. 进入「发布笔记 → 写长文 → 新的创作」。编辑器通常是 ProseMirror/Tiptap 的 `contenteditable`。
2. 单独填标题。正文优先通过剪贴板同时写入 `text/html` 和 `text/plain`，再粘贴到正文区；这样可保留二级标题、引用和列表。
3. 图片不要事后硬插到已经完成的长文中间。最稳的方式是按章节分块：粘贴一段 → 在普通空段落处上传图片 → 继续粘贴下一段。如此自然保持正确图文顺序。
4. 图片按钮在二级标题、引用或有序列表中可能被禁用。遇到禁用，先把光标移到普通段落，关闭激活的 H2/列表状态，再点击图片按钮。
5. 使用文件选择器时，先等待 `filechooser`，再点击图片按钮，最后传绝对路径。若当前浏览器安全策略拒绝本地文件，停下并让用户手动拖入，不绕过校验。
6. 每张图上传后检查编辑器里的图片数量、前后正文和自动保存时间。不要只凭工具调用成功就假定落点正确。

如果只能一次性粘贴全文，可先保留 `【配图1】` 之类的占位符；但不要依赖“点击占位段落”来精确设置光标，它在部分编辑器里不可靠。优先返回编辑器按章节重建，或把图片集中放在相邻章节末尾并如实核对。

## 一键排版与模板

完成正文和图片后点「一键排版」。平台会按内容长度生成若干可滑动页面，这一步是小红书原生排版，不等同于保留本地 HTML/CSS。

- 严肃商业/科技长文优先试「杂志先锋」「理性现代」「黑白极简」一类模板。
- 检查总页数、封面标题断行、章节是否被拦腰拆开、资料说明是否完整。
- 模板改变页数很常见；选择后重新检查每页预览。
- 平台生成的封面与文章插图是两件事。封面能识别主题，正文证据图仍应保留来源。

## 发布页

点击「下一步」后：

1. 等待所有长文图片生成完毕。
2. 核对标题、封面和页数。
3. 发布说明写 80–200 字，只概括冲突、核心发现和读者能得到什么，不重复整篇正文。
4. 添加 4–6 个相关标签；严肃长文不加无关热门话题，不使用 emoji。
5. 视内容真实性选择原创声明；转载或大量依赖单一报道时明确资料来源，不能包装成独家或亲历。
6. 点击发布后，只有出现成功页、跳转到笔记管理或列表中出现新笔记，才算发布成功。仍停留在编辑页不算成功；检查错误提示、验证码或安全校验。

## 完成判据

- 编辑器中标题、正文、H2、引用、列表和图片均存在且顺序正确。
- 实时截图与生成插图至少各一类；正文无占位符、无 emoji、无本地路径。
- 一键排版预览已逐页检查，封面与模板符合严肃主题。
- 发布后在笔记管理中确认状态，并回填 `note.md` 的 `status`、`published_at` 和后续 metrics。
