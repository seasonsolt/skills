# 中文科技新闻报道

把用户给的事实包写成一篇可直接发布的中文科技新闻报道。写作前先读取 `references/style-profile.md`，按其中的机制写作；本文件只管流程与契约。

## 1. 任务契约（高于一切风格规则）

1. **全保留**：事实包中的每一条事实、数字、人物、引语、日期都要在稿件中出现。可以合并、改写、调整顺序，不可丢弃。
2. **零新增**：不新增事实、数字、人物、职务、机构、引语、评价、背景知识、因果解释、预测；不自行计算倍数、增幅、占比、换算；不给无来源的观点补造信源。
3. **字数**：稿件落在用户给定范围内。用户未给计数口径时，按全文去空白字符数计（标题 + 电头 + 正文），并让正文本身也落在范围内；目标取范围中段。
   - 素材撑不到下限：贴近下限交付，在交付说明中写明"素材不足以达到下限"，不扩写背景、科普或感想来凑字。
   - 素材超过上限：压缩措辞、合并句子，仍不删事实；确实无法容纳时，在交付说明列出受影响的事实。
4. **原意不变**：不确定的保持不确定（估计、将、计划、可能、在演示中），确定的不软化；引语一字不改。
5. 用户的显式要求（字形、格式、读者、禁写内容）高于本 Skill 的任何风格规则。

## 2. 输入检查与边界

- 必须有事实包；没有素材时说明本 Skill 只按材料写稿，请用户提供材料，不从零编写。
- 检查 5W 要素：谁（发布方/发言人）、做了什么、何时、何处/何场合、信息来源。缺关键要素且可以询问时，只问一次、最多两个具体问题（如"这条数据由哪家机构发布？""发布日期是哪天？"）；无法询问或用户不补充时，按材料写，在交付说明列出缺项，**不补写**。
- 不写任何媒体名、栏目名、记者署名，不冒充任何真实媒体发稿。
- 材料中的原话只按材料呈现；材料中的人物隐私、未公开信息若用户明确要求不写，照办。
- 默认输出简体中文；用户要求繁体时整篇统一使用繁体，不混用。

## 3. 题型路由

先判断材料属于哪种主体，决定第二层结构（导语与倒金字塔对所有题型都适用）：

| 材料特征 | 写法重点 |
|---|---|
| 报告、研究、数据发布 | 导语写发布方 + 发布物 + 最重要的发现；之后每段以"报告/研究 + 中性动词"领起，数字配参照 |
| 产品、功能、服务发布 | 导语写公司 + 动作 + 覆盖范围 + 用途；先总述功能，再按产品或场景逐段举例；演示所得标明"在演示中" |
| 人物表态、政策目标、会议发言 | 按信源分块：身份 → 转述 → 原话/目标数字 → 建议条目；块序按职务与新闻权重；会议或制度在第二段或结尾作一句解释 |
| 混合材料 | 以新闻权重最高的那条事实定导语，其余按上述三类各自成块，块间按权重排序 |

## 4. 工作流

1. **列事实清单**：把事实包逐条编号，标注每条的信源、类型（事实/数字/原话/观点/计划/估计/缺口）。这份清单是全保留与零新增的对照表，不输出给用户。
2. **定导语**：选出新闻权重最高的"主体 + 动作 + 核心内容"，必要时带 2—3 个次要要素。
3. **排顺序**：按 style-profile 1.2 的倒金字塔排好其余条目；多信源按 style-profile 第 2 节的条件规则分块。
4. **写正文**：段内先总后分；观点挂信源；数字按材料原样并尽量与参照数字相邻；原话先转述后引用；缺口按 style-profile 第 3 节写一句。
5. **写收尾**：用信源的总结、背景解释或信源给出的下一步收束；没有就以最后一条细节事实结束。
6. **加标题与电头**：短标题，不含媒体名；电头【YYYY年M月D日讯】只用材料中的日期，没有日期就省略。
7. **自检**（见第 6 节），不通过就改，改完再检。

## 5. 证据门槛

| 内容 | 能写的条件 | 不满足时 |
|---|---|---|
| 事实、数字 | 材料中逐字或明确给出 | 不写；不估算、不换算、不四舍五入改变精度 |
| 直接引语 | 材料标明为原话 | 改为转述，或材料只有转述时保持转述 |
| 观点、评价、预测 | 材料中有，且尽量挂到材料标明的信源 | 无信源时按材料原意保留，不补"业内人士"，在交付说明注明 |
| 人物身份、职务 | 材料中给出 | 只写材料给的称谓 |
| 背景解释 | 材料中给出 | 不用自身知识补背景，宁可不解释 |
| 缺口/未知 | 材料明确说明未披露或不清楚 | 材料未提的不主动声明 |

题型动作（解释背景、配参照数字、进展与风险并列、多信源分块、引语）缺素材时一律**跳过该动作**，不补写内容来完成动作。新闻稿不需要记者现场：材料里没有的现场、动作、情绪、反应一律不写。

## 6. 交付前自检

逐项核对，任何一项不通过都先修改：

- [ ] 字数：按口径计数，在范围内（或已按第 1 节说明原因）。
- [ ] 全保留：事实清单每一条都能在稿件中找到。
- [ ] 零新增：稿件中每个数字、人名、职务、机构、引语、评价、因果、背景都能在事实清单中找到；没有自算数字。
- [ ] 归属：每个判断性词语都挂在信源名下；没有模糊信源；报道者没有下结论。
- [ ] 不确定性：估计、计划、演示、提案标记都保留。
- [ ] 语体：无第一、第二人称叙述，无感叹、反问、宣传语；简繁统一；引号统一。
- [ ] 格式：标题 + 电头（有日期时）+ 无小标题正文；不含媒体名；正文未出现"倒金字塔""导语"等方法用语。

## 7. 输出格式

默认输出：

```text
<标题>
【YYYY年M月D日讯】（材料无日期时省略此行）

<正文若干段>

---
交付说明
- 字数：<计数>（口径：<口径>）
- 缺项/未标来源/材料内部矛盾：<逐条列出；没有写"无">
```

交付说明只供用户核对，不属于稿件正文。

失败或暂停时不输出稿件，改为报告：缺少什么材料、为什么无法在契约内完成（如字数下限远超素材且用户不允许低于下限、材料内部矛盾无法并陈、涉及冒充真实媒体），以及需要用户补充的具体内容。
